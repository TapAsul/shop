# TapAsul — smart NFC digital cards

A fast, dependency-free static website for **TapAsul**. Every price, product, person,
question and contact detail lives in **one file**: `site.config.js`.

- No framework, no bundler, no database.
- Works on any static host (Cloudflare Pages, Netlify, GitHub Pages, plain shared hosting).
- A **PIN-locked booking dashboard** at `admin.html`.

## ⚡ Quick start

### Option A — Cloudflare Pages (recommended)

1. Push this folder to a GitHub/GitLab repo (or use Cloudflare's Direct Upload).
2. In Cloudflare Pages → **Create a project** → connect the repo.
3. Set these three fields:

   | Field | Value |
   |-------|-------|
   | **Framework preset** | None |
   | **Build command** | `node tools/build-seo.js` |
   | **Build output directory** | `.` |

   > If the site files sit in a `tapasul-site/` sub-folder inside your repo, set the
   > output directory to `tapasul-site` and the build command to
   > `node tapasul-site/tools/build-seo.js`.

4. **Deploy.** Cloudflare gives you a free HTTPS address like
   `tapasul.pages.dev`.
5. Put your domain in `site.config.js` → `brand.url`, push again, and add the
   domain under **Pages → Custom domains**.

### Option B — drag and drop

1. Run the build once: `node tools/build-seo.js`
2. In Cloudflare Pages → **Create a project** → **Direct Upload** → upload the
   whole `tapasul-site` folder.

### Option C — any other host

Upload the folder as-is. `robots.txt`, `sitemap.xml`, `manifest.webmanifest` and
the `<head>` tags are already generated, so nothing else is needed.

> `_headers` is Cloudflare-specific. On other hosts, ignore it (or copy the
> caching rules into your own config).

## ⚙️ Customising — everything is in `site.config.js`

Open `site.config.js` in any text editor. Save, refresh. That's the whole loop.

### 1. Brand

Your logo artwork lives in `assets/logo-frog.svg` (blue) and
`assets/logo-frog-white.svg` (white). Point `brand.logo` at your own file
and every logo on the site — header, footer **and** the consent popup —
switches to it.

`logo.js` holds an inline copy of the frog. It only takes over if the logo
file cannot be loaded (broken path, blocked request, offline preview), so the
logo can never turn into a broken picture. You never need to edit it.

```js
brand: {
  name: "TapAsul",          // the wordmark
  tagline: "More Than Just A Tap",
  description: "…",
  colors: { brand: "#0881ef", brandHover: "#0668bf", … },
  url: "https://your-domain.com",   // ← CHANGE ME  ← the ONE place for your domain
  email: "you@example.com",
  phone: "09XXXXXXXXX",
  address: "Quezon City, Metro Manila, Philippines",
  socials: { instagram: "https://…", facebook: "", tiktok: "" },  // "" hides a row
  logo: { mark: "assets/logo-frog.svg", markWhite: "assets/logo-frog-white.svg" },
  ogImage: "assets/social-preview.png",
}
```

### 3. Appointments & promo codes

This is how the booking page works. Change it here and the whole page follows.

```js
booking: {
  types: [
    { id: "standard", product: "card",    branding: "standard", name: "Standard Digital Card",
      note: "…", price: 999,  monthly: 149, badge: "Ready same day" },
    { id: "custom",   product: "card",    branding: "custom",   name: "Customised Digital Card",
      note: "…", price: 999,  monthly: 149, badge: "Most popular" },
    { id: "premium",  product: "premium", branding: "custom",   name: "Premium Digital Card",
      note: "…", price: 2499, monthly: 299, badge: "Logo included" },
  ],
  slots: ["09:00", "10:00", "11:00", "13:00", "14:00", "15:00", "16:00"],  // 24-hour
  days: [1, 2, 3, 4, 5, 6],     // 0 = Sunday — the days you are open
  leadDays: 2,                  // how far ahead people must book
  maxPerSlot: 4,                // how many bookings fit in one time slot
  durationMinutes: 30,          // how long one appointment takes
  depositPercent: 0,            // 0 = pay everything on the day
  location: { label: "Quezon City, Metro Manila", note: "…" },
  bringNote: "Bring your logo on a phone or a USB stick.",
  confirmationNote: "…", rescheduleNote: "…", cancelledNote: "…",
},

promo: {
  codes: [
    { code: "TAPASUL10", type: "percent", value: 10, label: "Launch discount — 10% off" },
    { code: "FRIENDS",   type: "fixed",   value: 100, label: "₱100 off" },
  ],
},
```

- `product:` says which product in `pricing.products` the option uses — that is
  the card the customer gets and the price they pay.
- `branding: "standard"` means the card ships with your printed TapAsul artwork,
  `"custom"` means the customer sends their own logo. The premium option is
  `"custom"` because the logo is included in the price.
- `type: "percent"` takes 10% off the card price; `type: "fixed"` takes off a
  fixed peso amount. Both codes are live on the site the moment you save.

The scrolling row of customer tap pages and the call to action under it.

```js

  sub: "This is what your customers land on when they tap.",
  baseUrl: "https://portal.tapasul.com/r/",

    { name: "1234", tint: "#c9b49b" },     // tint = the round dot colour
    …
  ],
  cta: {

    text: "Every TapAsul card comes with its own profile page …",
```

- Add a customer → add one line to `people`. Remove one → delete the line.
- `tint` is the colour of the dot (any CSS colour).
- `href` can be set per person if their page is somewhere else.
- The strip travels **to the right** on one straight line, and pauses when the

  stops moving but stays a single line they can swipe by hand.

#### The guided booking funnel (4 steps)

The page now walks a visitor from “I want a card” to “booking sent” in four
steps, and nothing they type is lost on the way:

| # | What they do | Where they land |
|---|---|---|
| 1 | Click **Select Digital Card** / **Select Premium Card** on a product card | The **Booking** page, with that card already picked and the cursor in the page-name box |
| 2 | Type the name they want | The address updates live: `portal.tapasul.com/r/kusina-ni-maria` |
| 3 | Click **Claim my free page** on Home | The **comparison table** on Product & Pricing (`pricing.html#compare`) |
| 4 | Click **Choose Standard** / **Choose Premium** under the table | The **Booking** page, with that tier picked and their page address in the summary |

- The name is turned into a **web address** for them: spaces become dashes,
  capitals become small letters (`Kusina ni Maria` → `kusina-ni-maria`).
- Their name is copied into **Full name** in the booking form (only if that box
  is still empty — if they typed their own name there, that wins).
- The booking summary shows a **“Your page”** line, the confirmation email
  includes it, and `admin.html` shows it under **“Their free page”**.
- Everything is still editable in `site.config.js` → `showcase.cta`:
  `urlBase` (the address), `nameLabel`, `namePlaceholder`, `button` (the
  button text) and `next` (where the button sends them — `#compare` by default).
- The page name they type is kept for the tab, so moving from Home to Booking
  or Product & Pricing and back does not lose it.

### 4b. The comparison table (Product & Pricing page)

`pricing.html` carries **one** comparison — the Standard vs Premium table. It is
driven by the top-level `compare` block in `site.config.js`, so you never touch
HTML to change a row.

```js
compare: {
  eyebrow: "Compare",
  title: "Standard or Premium",
  sub: "Same tap, same free page. The Premium card is the one with your own logo on it.",
  columns: [
    { product: "card",    label: "Standard", note: "Our artwork" },
    { product: "premium", label: "Premium",  note: "Your own design", accent: true },
  ],
  groups: [
    {
      title: "The card itself",
      // every row has one label and one value per column
      rows: [
        { label: "Card finish",  values: ["Sticker print on PVC", "UV-printed PVC"] },
        { label: "Your own logo", values: [false, true] },   // false = dash, true = tick
      ],
    },
    // "The page it opens", "Features you can switch on", "Getting it made" …
  ],
  note: "Hosting starts the month after your card is set up. …",
}
```

- A value is either **plain words**, `true` (a tick) or `false` (a dash).
- `product` must match a key in `pricing.products` (`card`, `premium`); the
  prices in the header row come from there, so they stay in step with the cards.
- The buttons under the table (**Choose Standard** / **Choose Premium**) open
  `booking.html` with that tier already picked.
- On a phone the row labels stay pinned and the two columns swipe sideways,
  with a short “Swipe to compare →” hint.

> **The old “What's inside your digital card?” block was removed.** It repeated
> what the table already lists, so the page had the same information twice.
> The table is now the only comparison on the site.

### 4c. The “My work” gallery

This is where you show the cards you have made — your clients' work. It sits on
the **Home** page, straight under the hero and before the “Every card gets its
own page” demo. The section is driven by one block in `site.config.js`, so you
never touch HTML.

```js
myWork: {
  enabled: true,
  eyebrow: "My work",
  title: "Cards we have made",
  sub: "Real TapAsul cards in the wild — a steel fabricator, a ramen shop and a freelancer.",

  // Add your photos of finished cards here.
  // 1. Put the picture files in  assets/work/
  // 2. Add one line per picture below:
  //    { image: "assets/work/kusina.jpg", title: "Kusina ni Maria",
  //      note: "Restaurant · Quezon City", href: "https://portal.tapasul.com/r/yourname" },
  //    title, note and href are optional — a picture on its own is fine.
  //    Add "href" and the tile becomes clickable.
  items: [
    { image: "assets/work/jenny-steel.jpg",    title: "Jenny Joven Beria",
      note: "Steel fabrication · ALR Steel Fabrication and Services OPC" },
    { image: "assets/work/melbert-ramen.jpg",  title: "Melbert Pereda",
      note: "Food industry · Founder & CEO, Brother's Ramen" },
    { image: "assets/work/arcega-freelance.jpg", title: "King Arcega",
      note: "Freelancer · Affiliate marketing creator, theshop101.ph" },
  ],
},
```

- **Tap a tile and the picture opens** over the page. Tap the picture again
  and it jumps to its real size (2048 px wide, scrollable) so a QR code or a
  small detail can actually be read; **Open full size** opens the file itself.
  Arrow keys or a sideways swipe move between cards, **Esc** or the **×** closes
  it and puts the keyboard back on the tile you came from.

**Three tiles are already in place** (Jenny — steel fabrication, Melbert — food,
King Arcega — freelancer). Each picture is 1024 × 645 (the tile's shape) and
shows two screens of that client's live page side by side. Replace a file with
the same name and the tile updates — no config change needed.

- Put the photos in **`assets/work/`** (create the folder next to `assets/`'s
  other sub-folders) and give each one a short name.
- `href` turns the tile into a link — use it to send people to that client's
  live profile page.
- The grid adapts: one column on a phone, as many as fit on a wide screen.
- While `items` is empty the section shows a short note telling you what to do
  — add the photos and the tiles appear automatically.
- To hide the whole section, set `myWork.enabled = false`.

## The card in the hero

The card at the top of the home page is a **real 3D card**: drag it (or use the
arrow keys when it is focused) and it turns over — the front is the printed
card, the back is the QR code. It turns slowly on its own, stops while you are
dragging, and pauses when it scrolls out of sight.

It is plain CSS 3D — no 3D library, so the page stays light. To swap the
pictures, replace `assets/card-front.jpg` and `assets/card-back.jpg` with your
own artwork (keep the same 1024 × 645 size so the proportions stay right).

#### Booked days and times are blocked

The date field on the booking page is a small calendar, and times that are
already taken show why:

- A day where **every** time has reached `booking.maxPerSlot` is greyed out,
  struck through, labelled **“Fully booked”** for screen readers, and cannot be
  clicked. Closed days (anything not in `booking.days`) are greyed the same way.
- A time that is full is disabled and says **“Full”**; a time with one place
  left says **“1 left”**.
- The line under the date tells you how many times are still free, and if a day
  fills up while the page is open you are asked to pick another day.

Where the numbers come from: bookings made in this browser (`localStorage`),
plus `GET /api/availability?from=…&to=…` for everyone else's. That endpoint
ships in `functions/api/availability.js` and returns **counts only** — no
personal data — so it is safe to leave public. Without D1 (or on a host with no
Functions) it quietly returns nothing and the browser's own bookings still
block. `api/availability` is the empty static fallback so the request never
404s on a plain static host.

#### The “choose your feature” picker in the booking form

Standard-card customers pick **1** of the featured features while booking (the
table on the pricing page says **“Pick only one”**). The options come from
`inside.featured` above — one list, two places.

```js
booking: {
  featurePick: {
    enabled: true,
    max: 1,                                  // how many they may pick
    label: "Your feature",
    note: "Your Standard card includes one feature of your choice. Pick it below.",
    premiumNote: "Premium includes every feature — nothing to pick.",
    appliesTo: ["standard", "custom"],       // booking types that can pick
  },
}
```

- Premium bookings skip the picker and show `premiumNote` instead.
- A second pick is refused with a short message.
- Want to give them two later? Set `max: 2` and reword `note` — the whole form
  follows the number.
- The choice is saved with the booking, appears in the summary panel, in the
  confirmation email and in the admin dashboard. It does **not** change the price.

## 🩺 If the page looks empty — the boot check

Every page has a small check that runs on its own. If `index.html` loads but
`script.js`, `site.config.js` or the `assets/` folder did **not** arrive, the
page shows an amber bar at the top saying so, instead of empty grey boxes.

> **This page did not finish loading.**
> index.html arrived, but the rest of the site did not. The whole folder has
> to be uploaded together — `script.js`, `site.config.js`, `logo.js` and the
> `assets/` folder must all sit next to index.html. Then refresh.

If you ever edit the small script block marked `BOOT CHECK` at the bottom of
`index.html`, run `node tools/update-csp-hash.js` so Cloudflare keeps allowing
it.

## 🔁 The build step — why it exists

`site.config.js` is the single source of truth, but search engines read **static
files**. So after you change the config, `tools/build-seo.js` copies the values
into the places that need them:

| File | What gets written |
|------|-------------------|
| `robots.txt` | your domain, and `Disallow: /admin.html` so the dashboard stays out of Google |
| `sitemap.xml` | your domain |
| `manifest.webmanifest` | app name, colours, icons |
| `index.html` | `<title>`, description, canonical, Open Graph tags, JSON-LD |
| `admin.html` | `noindex` + canonical |

Run it with:

```bash
node tools/build-seo.js
```

It also prints a **"Before you publish" checklist** so you can't forget the
domain, the PIN or the order endpoint.

> On Cloudflare Pages this runs automatically on every deploy (set the build
> command). If you deploy by hand, run it before uploading.

## 🔐 Admin dashboard — `admin.html`

A separate page for running your appointments. Open **`/admin.html`** (there is a
by typing its address) and unlock it with the PIN. The link is deliberately **not** in the site footer — the public shop never advertises the dashboard.

| Tab | What it does |
|-----|--------------|
| **Overview** | Revenue, order count, units, average order, monthly hosting, and how many orders still need action. Plus a 14-day bar chart, a product mix breakdown and the latest orders. |
| **Bookings** | Every appointment in a searchable, filterable table (status, card, date and time slot). Change a status inline, open the full detail, email the customer with one click, delete it, or export the filtered list to CSV. |
| **Pricing** | A **cost & selling-price calculator** (materials, labour, setup, courier, monthly overheads → break-even price → recommended price with your margin), plus a price editor that gives you a ready-to-paste `site.config.js` block. It never writes to your files — you paste it in yourself. |
| **Setup** | Switch the order mode (click to copy the line), a go-live checklist, order-storage controls, a **Download site.config.js** backup button, and all your business details in one place. |

### How orders get into the dashboard

Every submission is saved to the visitor's browser, so `admin.html` always has a
local copy. To see orders from **every device**, connect a Google Sheet:

1. Create a Google Sheet with a header row:
   `id, submittedAt, name, email, product, productId, quantity, unitPrice, monthlyHosting, discount, total, currency, status, note, profileName, profileUrl`
   (`profileName` and `profileUrl` are the free page the customer asked for —
   leave them in so you can set the page up straight away.)
2. **File → Share → Publish to web → CSV**, and copy the URL.
3. Paste it into `order.admin.remoteUrl` in `site.config.js`.
4. Set `order.mode` to `"local"` and `order.endpoint` to a Google Apps Script or
   Formspree endpoint that appends a row to the same sheet.

### The PIN is a soft lock

`order.admin.pin` lives in `site.config.js`, which is a public file. It keeps
casual visitors out of the dashboard, but anyone who views source can read or
change it. For a real lock, serve `admin.html` behind HTTP basic auth (most
hosts support this in a `.htaccess` or a dashboard setting) or keep the page at a
URL only you know. `_headers` also sends `X-Robots-Tag: noindex` for it.

## 💰 Working out your selling price

Read **[`PRICING-GUIDE.md`](PRICING-GUIDE.md)** — it walks a new business owner through raw
materials, labour, transport, overheads and the exact formula, with a worked example.

The **Pricing** tab of `admin.html` has the same maths as a live calculator:

```
cost per unit  = materials + labour + (setup ÷ batch qty) + (courier ÷ units per parcel)
landed cost    = cost per unit + (monthly overheads ÷ monthly units sold)
break-even     = landed cost
target price   = break-even ÷ (1 − discount %) ÷ (1 − margin %)
```

It also tells you how much cash a batch needs, how many units you must sell each month to
cover your overheads, and what one card kept for 12 months is worth in hosting.

## ⚖️ Legal pages

`terms.html`, `refund-policy.html` and `privacy-policy.html` are written and linked in the
footer. They are generated from `site.config.js` → `legalPages`, so you can change the
wording without touching code.

They cover the things that get small businesses into trouble: bookings are confirmed by
email, custom-printed goods become non-refundable once printing starts, faulty goods are
replaced, delivery damage must be reported within 48 hours, customer data is kept for 24
months, and the customer's rights under the Data Privacy Act are listed with a named DPO.

> These are a solid starting point, **not legal advice** — have a Philippine lawyer read them
> before you take real money.

## 🔐 Privacy consent gate

Visitors get a **Accept / Decline** privacy notice on their first visit.

- **Accept** → analytics may load and the booking can be saved on the device.
- **Decline** → no analytics script is loaded, nothing is stored, and the site keeps working.

The choice is saved in `localStorage` under `tapasul_consent_v1`. Change the wording in
`site.config.js` → `privacyConsent`, or set `privacyConsent.enabled = false` to remove the
gate entirely.

## 🚀 Before you go live — 3 things only you can do

| # | What | Where |
|---|------|-------|
| 1 | **Real domain** | `brand.url` — drives canonical, og:url, sitemap, robots. Then run the build. |
| 2 | **Admin PIN** | `order.admin.pin` — still `1234`, change it before publishing |
| 3 | **Order delivery** | `order.mode` — `"worker"` saves every booking in Cloudflare D1 and emails it to you (see `BOOKING-SETUP.md`). `"email"` opens the visitor's mail app. `"formspree"` + `order.endpoint` also works. |
